# Maskrom Studio 用户体验审计（2026-11）

审计对象：main 上的 e04350b（Armbian 全部映像那一版）。方法：按 TESTING.md 和
`scripts/readme-shots.mjs` 的方式构建并运行真实的 Electron 应用（隐藏窗口，假发布数据，
`test/fixtures` 里的 Windows ISO，升级流程用 `test/electron/fake-board-worker.ts` 的假板子），
在 1100x780、1093x614（1366x768 笔记本 125% 缩放后的可用区域）和 720x480（应用允许的最小窗口）
下，用中英文、明暗两种主题截图；另外用真实的 MaskROM worker、不接板子，复现"找不到开发板"；
用 Playwright 逐个按 Tab 检查键盘焦点顺序，并统计无名按钮和图片的替代文本。没有接真板，
也没有在 Windows 主机上运行（Windows 下的页面用只在开发构建里生效的
`WOA_IMAGER_SHOW_PLATFORM=win32` 渲染）。

截图都在 `docs/imgs/ux-audit/`（before 为改动前，after 为改动后），其余引用的是
`docs/imgs/` 里已经重新生成的 README 截图。

## 优先级怎么定

影响 × 成本，各分三档：

- **P1**：影响大（会让人卡住、误操作或损坏板子上的内容），改动小、风险低。本次已实现。
- **P2**：影响中等，或者影响大但改动面大。写进待办，不涉及产品取舍的下次直接做。
- **P3**：小问题，顺手时再改。
- **需要用户决定**：改变流程结构、删减功能、或者改变数据和安全语义的，只写建议，不实现。

## 三类用户走一遍

**小白，简单模式，Windows 电脑，想装 Win11 或 Armbian 桌面。** 选板子（有照片）、选做什么
（四项，每项一句说明）、准备（刷机模式步骤、照片、驱动说明）、确认（勾选"我知道这些内容会被清除"
后才能开始），连上板子后还会再确认一次。信息架构清楚，每一步都有标题和一句引导，"更多选项请使用高级模式"
放在了合适的位置，Armbian 桌面用卡片和截图区分，GNOME 标了推荐。最容易卡住的三个地方：
Windows 上的 WinUSB 驱动（原来只有一句话）、找不到开发板（原来只有一句英文原因，没有排查方向）、
网络失败（原来直接显示 `net::ERR_NAME_NOT_RESOLVED`）。失败后点"完成"会回到第 1 步，
虽然选择都还在，但人会以为要从头再来。

**有经验的开发者，高级模式。** 任务按 Windows、UEFI 固件、Linux 和出厂系统分组；Windows 映像步骤把
架构、内部版本、启动文件、版本列表都读出来，拒绝 x64 和 24H2 时说明了原因；磁盘布局有实时预览；
Review 把擦除范围精确到扇区，并给出写入量和大致耗时；连接板子后再显示 eMMC 实际容量和要删除的分区，
再确认一次。整体可信、信息密度合适。问题集中在运行页：开发板应答后的确认卡片在进度条下面，
小窗口时看不到，进度没有速度和剩余时间，出错的那一步没有标出来。

**中文用户。** 简体中文覆盖完整，没有漏翻的键（`test/i18n.test.ts` 也在检查），语气自然，
"刷机模式""板载存储""引导组件"等用词贴近国内社区。问题：Windows 的 build 和 edition 都译成"版本"，
同一张表里两列都叫版本；"开发板板载存储"读着重复；几处界面文字写死了英文（步骤导航的无障碍标签、
更新对话框的"Release notes"和加载圈）；来自底层的英文错误信息有一部分没有中文对照。

## 本次已实现（P1）

每条一个提交，均在分支 `ux-audit-2026-11` 上，CI 通过后合入 main。

### 1. 失败页说清楚下一步，"重试"不丢位置

- 现状：`before-run-network.png`，失败后只显示原始错误码；`before-done-step1.png`，点"完成"回到第 1 步。
- 问题：错误不可操作；用户以为选择都丢了，要从头再点四次"下一步"。
- 改动：网络错误显示为"无法连接下载服务器（net::ERR_...）。请检查这台电脑的网络连接，然后重试。"，
  原始代码保留在句子里方便搜索；失败时按钮变成"重试"（简单模式等同再按一次"开始"，高级模式先弹出
  原来的确认对话框）和"返回步骤"（回到确认/Review 那一步，所有选择保留，`after-back-to-confirm.png`）。
  成功时仍然是"完成"，回到第 1 步。
- 优先级：P1。提交 293a95e。

### 2. 找不到开发板时给出排查清单

- 现状：只有"No board in Maskrom mode was found."
- 问题：这是新手最常遇到的失败，原因却有四五种。
- 改动：在错误下方加"请检查"卡片：是否真的进入了刷机模式（正常启动、屏幕有画面就说明没有进入）、
  数据线和接口、Windows 上的 WinUSB 驱动或 Linux 上的 udev 规则（只显示当前系统那一条）、
  是否只连了一个 Rockchip 设备。见 `after-noboard-windows.png`、`after-noboard-linux-zh.png`。
- 优先级：P1。提交 293a95e。

### 3. Zadig 驱动安装改成编号步骤

- 现状：`before-ready-no-zadig.png` 是 Linux 下的样子；Windows 下原来只有一句话。
- 问题：缺两个关键点：Zadig 只有在开发板处于 MaskROM 模式并已连接时才看得到它；有时要点
  Options、List All Devices 才会列出来。docs/install.md 里写了，应用里没写。
- 改动：四步编号列表，和 docs/install.md 一致；README 截图新增 `simple-ready-windows.png`
  （中英各一张）。为了能在 Linux CI 上截出 Windows 的页面，加了只在未打包构建里生效的
  `WOA_IMAGER_SHOW_PLATFORM`。
- 优先级：P1。提交 d28040c。

### 4. 写入中途取消或关闭窗口要先确认

- 现状：运行页的"取消"和窗口关闭按钮都会立即中断。
- 问题：写到一半的 eMMC 可能无法启动；泰山派 3M 没有 MaskROM 按键，要重新短接焊盘才能救回来。
  没有撤销，所以需要一次确认。
- 改动："取消"弹出"现在停止？"，说明后果，按钮为"停止"（危险色）和"继续"（`after-stop.png`）；
  运行中关闭窗口时由主进程弹出系统对话框，文字由页面按当前语言传过去（`setBusy`）。
  隐藏窗口的测试运行不弹。
- 优先级：P1。提交 1b8636f。

### 5. 开发板应答后的确认卡片放到进度上方

- 现状：`before-confirm-below.png`，卡片在三条进度条之后，1366x768 屏幕上要滚动才看得到。
- 问题：这时整个流程在等用户点按钮，按钮却在视线以外，用户会以为卡住了。
- 改动：卡片放在标题下面第一位（`after-confirm-first.png`）；没有确认卡片时，标题下多一行
  "在显示'完成'之前，请保持开发板连接，也不要关闭这个窗口。"
- 优先级：P1。提交 293a95e。

### 6. 简单模式确认页写明耗时

- 现状：`docs/imgs/simple-confirm.png` 改动前写的是"需要一段时间"，高级模式的 Review 里其实有数字。
- 改动：新增"耗时"一行：Windows 为"通过 USB 写入大约 5 到 15 分钟（尚未实测），然后开发板自行安装
  还要 20 到 40 分钟"；Armbian 先写下载大小，并说明写入耗时尚未实测。写完后的提示不再用"暂存"这种术语。
- 优先级：P1。提交 b8ff2c1。

### 7. 中文术语和写死的英文

- 改动：Windows 的 build 统一为"内部版本号"（与微软中文一致），edition 保持"版本"；"开发板板载存储"
  改为"板载存储中……"；去掉一处句中多余空格；步骤导航的无障碍标签、更新对话框的"更新说明"链接和加载圈、
  Windows 版本表的选择列表头都改为走翻译；简单模式"原厂系统包"英文标签首字母大写。
- 优先级：P1。提交 4edf4c3。

### 8. 清除缓存只列出存在的东西

- 现状：`before-clear-cache-zh.png`，没下载过映像时显示"下载的映像：0 bytes，文件数：0（-）"。
- 改动：空的类别不列出；什么都不删时"删除"按钮不可用。
- 优先级：P1（成本极低）。提交 3feb4cc。

### 9. 屏幕阅读器把开发板名字读两遍

- 现状：简单模式的开发板卡片以整张卡的文字作为名称，照片的替代文本又是板名。
- 改动：照片的替代文本留空（标题已经说了板名）。
- 优先级：P1（成本极低）。提交 82c3f1f。

## 需要用户决定

### D1. 简单模式里的"恢复原厂系统"还没在板子上测试过

- 现状：`simple-factory-untested.png`。高级模式这一步有"尚未在开发板上测试"的提示
  （TESTING.md 也列为未测试），简单模式没有。
- 问题：最没有经验的用户拿到的是最不确定的路径，而且没有被告知。
- 选项：(a) 测试通过前从简单模式里拿掉这一项；(b) 简单模式也显示同样的提示；(c) 保持现状。
  建议 (a)，等硬件测试通过再放回来。

### D2. "准备"这一步不检测开发板

- 现状：在"准备"页不接板子也能点"下一步"，要到确认页点"开始"之后才发现没连上。
- 建议：在"准备"页实时显示"已检测到 MaskROM 模式的开发板"或"还没有检测到"，没检测到时"下一步"
  仍可用但给出提示。需要页面周期性枚举 USB，Windows 上没装驱动时还要能区分"有设备但没有驱动"。
  这会改变步骤的含义，所以列为需要决定。

### D3. 应用自己安装 WinUSB 驱动

- 现状：依赖用户下载 Zadig 并照步骤操作（本次已把步骤写清楚）。
- 建议：内置 libwdi（Zadig 的底层）一键安装，需要管理员权限，docs/install.md 也提到"尚未测试"。
  工程量大，且涉及签名和杀毒软件误报，需要决定是否值得。

### D4. 大文件下载不能续传

- 现状：`src/main/release-download.ts` 在失败或取消时删除 `.part`，WinPE、Armbian 桌面映像
  （约 1 GiB）断网后要从头下。下载完成后会用 SHA-256（Armbian 还有 OpenPGP 签名）校验，缓存命中时
  也会重新校验，这部分做得好。
- 建议：保留 `.part`，用 HTTP Range 续传，最后仍按整体 SHA-256 校验，不对就删掉重下。
  会改变缓存里会出现什么文件、清除缓存要不要统计 `.part`，所以需要决定。

### D5. 高级模式的确认次数

- 现状：Review 页按钮、弹窗确认（整盘擦除还要勾选）、连接后再确认一次，最多三次。
- 建议：保留"连接后看到真实容量再确认"这一次（它带来的是新信息），把 Review 后的弹窗只留给
  写本机 SD 卡或 U 盘、没有第二次确认的那些任务。属于流程结构，需要决定。

### D6. 整盘擦除前的备份

- 现状：写 Armbian 或出厂映像会清掉 eMMC 上的 UEFI 设置和 Windows，不可撤销；固件升级时会先把
  UEFI 设置（nvdata）存到电脑上，整盘写入时不会。
- 建议：整盘写入前同样先把 nvdata 和分区表读下来存一份（几十 KB，几秒钟），在确认卡片里说明保存位置。
  这是"可撤销性"上最便宜的一步，但会改变写入流程，需要决定。

### D7. 最小窗口太矮

- 现状：`min-window-ready.png`、`min-window-confirm.png`、`min-window-zh-dark.png`。720x480 时
  内容区只剩约 250 px，确认页"清除"那一行要滚动才看得到；1093x614 时正常。
- 建议：最小高度提高到 560，或者窄窗口时把顶栏和步骤条合并。前者会影响极小屏幕，需要决定。

### D8. 术语表定稿

- 现状：简单模式说"刷机模式"，高级模式说"MaskROM 模式"；底层英文错误里写作"Maskrom"。
- 建议：按下面的术语表定稿，底层错误文字统一为 MaskROM（会改 CLI 的输出文字）。

## 没有发现问题的地方

- 键盘：Tab 顺序为顶栏（模式、语言、设置）、步骤导航、内容、底部按钮；开发板卡片是单选组，方向键可切换，
  空格选中；焦点框可见（`keyboard-focus.png`）。没有找到没有名字的按钮。
- 深色模式：所有页面都检查过，对比度用的是 PatternFly 的 subtle 文字令牌，没有自定义颜色。
- 空状态：Armbian 列表加载中、找不到磁盘、没有 U 盘都有一句说明，告诉人要做什么。
- 危险操作：简单模式要勾选才能开始，连接后再确认；固件升级不写分区表并读回比对。
